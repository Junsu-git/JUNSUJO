# 조준수 포트폴리오 개편 설계안

상태: 구현 반영. 상세 검증 결과는 verification.json 및 verification.md 참고.

후속 요청 반영: 대표 프로젝트 4개는 이미지 탐색·담당/기여도·태그·상세보기로 구성한 2×2 카드로 변경했다. 아래 최초 설계의 가로형 카드 규칙은 그 외 프로젝트 목록에 유지한다. 최신 카드 구성과 이미지 추가 방법은 project-cards.md를 따른다.

## 목적

교수와 채용 담당자가 소개, 담당 역할, 문제 해결 과정과 학습 성과를 빠르게 확인할 수 있게 한다. 사용자 요청의 인적 사항과 네 개 대표 프로젝트, 다섯 개 과제, 기존 자료와 URL을 보존한다. 새로운 성과나 협업 일화를 만들지 않는다.

## 현재 파일에서 확인한 문제

- 정적 HTML 10페이지가 공통 CSS·JS와 페이지 내부 스타일을 함께 사용한다. 과제 페이지의 내부 스타일은 수백 줄에 이른다.
- assignment-02.html과 assignment-04.html에서 공통 JS를 중복 로드한다.
- ThemeManager에 storage 이벤트 수신이 없어 열린 다른 탭의 테마 변경을 반영하지 못한다. 초기 테마 스크립트와 ThemeManager가 읽는 저장 키도 다르다.
- 상세 페이지는 긴 개요와 메타 정보 뒤에 성장 평가를 배치한다.
- 메인 소개와 경력에 요청보다 장황한 수식어가 남아 있다.
- 약국 상세에는 '연산 소요 시간 94% 단축' 등 근거를 이 저장소에서 아직 확인하지 못한 수치가 있다. 기존 HTML의 서술 자체를 검증 자료로 취급하지 않는다.

## 구현 방식 비교

1. **기존 정적 페이지 + 공통 디자인 시스템 재정비 (추천)**: 현재 URL과 GitHub Pages 호환성을 유지하고, 빌드 도구 없이 열 수 있다. 페이지별 콘텐츠는 HTML에 남겨 검색과 읽기 접근성을 유지한다.
2. 기존 CSS 뒤에 보정 스타일 추가: 수정량은 작지만 스타일 우선순위와 중복 구조가 남아 이후 수정 시 다시 깨질 위험이 있다.
3. 프레임워크로 전환: 템플릿 공유는 쉽지만 현재 요구에 불필요한 의존성과 배포 변경이 생긴다.

추천안은 HTML 콘텐츠를 유지하면서 레이아웃·시각 토큰·내비게이션·테마 동작을 공통 파일에서 관리하는 방식이다.

## 시각 방향

- 흰색과 차콜 중심, 얇은 경계선, 작은 모서리 반경, 과하지 않은 여백을 사용한다. 큰 배경 광원과 발광 효과를 제거한다.
- 아이콘은 currentColor 기반 stroke SVG만 사용한다. 기존 프로젝트 이미지의 색상은 보존한다.
- 색상은 수상과 의미 구분에만 제한한다. 밝은 테마의 앰버 #6d3e00, 포레스트 #144919, 네이비 #0842a0를 실제 배경과 조합하여 대비율 7:1 이상으로 검사한다.
- Pretendard와 시스템 대체 폰트를 사용하고 제목·본문·캡션·코드 크기와 행간을 공통 토큰으로 정의한다. 문장 안의 강제 줄바꿈을 제거한다.
- 태그는 한 항목을 한 줄로 유지하고 태그 목록만 다음 줄로 흐르게 한다. 긴 설명을 태그로 만들지 않는다.

## 메인 페이지

- 전체 레이아웃은 데스크톱에서 좌측 프로필과 우측 본문으로 나눈다. 프로필은 sticky로 유지하며 화면 높이가 작을 때 링크가 잘리지 않게 한다.
- 본문은 max-width: 1040px; margin: 0 auto로 제한하고, 모든 섹션을 같은 main 안에 둔다. 화면이 좁으면 프로필을 상단으로 옮기고 단일 열로 전환한다.
- 순서: 간결한 소개 → 대표 프로젝트 4개 → 과제 5개 → 기술과 근거 → 학력·경력 → 연락처. 수상은 관련 프로젝트 배지와 이력으로 표현하고 중복 홍보 카드를 줄인다.
- 대표 프로젝트와 과제 모두 horizontal-project-slot을 사용한다. 데스크톱은 이미지/번호, 제목·역할·요약·태그, 상세 링크의 가로 배치이며 모바일은 한 열로 접힌다.
- 대표 프로젝트 순서는 약국, 누리살이, 최후의 전사, 2026 캡스톤 디자인을 유지한다. 마지막 항목의 2026은 사용자가 지정한 프로젝트 이름이므로 남긴다.
- 소개 문안: '기본기를 다지며, 팀과 함께 확장 가능한 구조를 고민하는 게임 클라이언트 개발자가 되고 싶습니다. 구현 과정과 데이터를 근거로 소통하려고 합니다.'
- 학력은 '유한대학교 컴퓨터소프트웨어공학부 게임콘텐츠전공 · 전문학사 졸업예정 · 3학년'으로 표기한다.
- 복무는 '사회복무요원 · 2021.08.12 ~ 2023.05.11 · 복무 만료'로만 표기한다.
- 협업과 갈등 사례는 상세 페이지에서 다룬다.

## 상세 페이지 9개

- 공통 순서: 간결한 제목 → 경험 평가/Before·After → 프로젝트 개요·역할 → 구현 또는 분석 → 문제 해결·협업 → 자료·회고.
- 페이지 제목 아래 첫 콘텐츠 섹션이 성장 평가가 되도록 한다. 불필요한 장문 개요와 메타 정보가 이를 밀어내지 않는다.
- 동일한 헤더, 본문 폭, 타이포그래피, 카드, 표, 코드 블록, 이미지 설명을 사용한다. 상세 분석 자료와 기존 인터랙션은 보존한다.
- 데스크톱 TOC는 sticky, 모바일은 가로 스크롤 가능한 목차로 제공한다. 앵커 대상, 현재 항목 표시, 헤더에 가리지 않는 점프 위치를 확인한다.
- 탭 안의 내용을 가리키는 TOC는 해당 탭을 먼저 열고 이동한다. 숨겨진 콘텐츠로 점프하지 않게 한다.
- 실제 갈등 사례의 근거가 없는 경우 일화를 작성하지 않고 '협업 사례: 추후 수정'으로 남긴다. 미확인 수치·직책·완료 상태도 단정하지 않는다.

## 테마와 접근성

- CSS 로드 전에 같은 초기화 파일을 실행해 저장된 모드와 시스템 모드로 data-theme를 설정한다. 기본값과 저장 값 오류 처리도 통일한다.
- 정식 저장 키 하나를 사용하고 기존 두 키의 값은 초기 1회 호환 처리한다. 같은 페이지, 페이지 이동, 다른 탭의 storage 이벤트, 시스템 설정 변경을 처리한다.
- localStorage 사용이 차단되어도 버튼과 시스템 모드가 동작한다.
- 테마 컨트롤은 휴대전화 앱이나 네이버 웨일의 설정처럼 화면 우측 하단의 항상 같은 위치에 원형 버튼으로 표시한다. 스크롤과 페이지 이동에도 뷰포트 기준 위치를 유지하고, 모바일의 안전 영역을 확보한다.
- 원형 버튼을 클릭하면 라이트·다크·시스템 원형 선택 버튼이 그 위로 세로로 펼쳐진다. 가로 메뉴나 화면 중앙 팝업으로 열지 않는다. 모드 이름은 각 버튼 옆에 짧게 표시한다.
- 테마 선택 즉시 적용하고 선택 목록을 접는다. 컨트롤 바깥 클릭 또는 열린 상태에서 기본 버튼을 다시 클릭해도 접는다. 기본 원형 버튼은 계속 같은 자리에 남는다.
- 선택 상태, aria-expanded, 키보드 접근, Escape 닫기, 포커스 복귀를 지원한다.
- 닫힌 테마 버튼은 키보드로 접근되지 않게 한다. prefers-reduced-motion에서는 펼침과 부드러운 스크롤 애니메이션을 줄인다.
- 본문 바로가기, 명확한 focus-visible, 표·코드 영역의 국소 가로 스크롤을 제공한다.

## 수정 범위와 검증 기준

- index.html, projects/*.html, assignments/*.html, assets/css/portfolio-system.css, assets/js/portfolio-system.js 및 공통 테마 초기화 파일.
- 문서와 원본 이미지, 기존 프로젝트·과제 URL을 보존한다. 배포·커밋·푸시는 수행하지 않는다.
- 10페이지의 HTML 구조, 중복 ID, 로컬 링크·이미지·목차 대상, 스크립트 중복, 컬러 이모지 잔존 여부를 검사한다.
- 데스크톱과 모바일에서 모든 섹션의 정렬, 가로 넘침, 고정 영역 겹침, 카드 배치와 TOC를 검사한다.
- 밝음·어두움·시스템 모드, 새로고침, 페이지 이동, 다중 탭 동기화, 저장소 차단 시 동작을 검사한다.
- 실제 브라우저 확인 결과와 정적 검사 결과를 구분하여 보고한다. 확인하지 못한 항목은 통과로 표기하지 않는다.
