01. 게임 플레이 루프 분석 및
FSM 상태 전이 프로토타입

핵심 플레이 루프(Explore → Encounter → Action → Reward)의 규칙을 정립하고, Unity 환경에서 FSM(Finite State Machine) 패턴을 적용하여 적 AI의 순찰·추적·공격 상태 머신을 구현한 1주차 과제 결과물입니다.

과목명 게임 프로그래밍 실습
수행 형태 1인 개인 과제 (기획 & 구현)
사용 도구 Unity 2022.3 LTS · C#
제출 결과물 WebGL 실행 빌드 & 분석 보고서
SECTION 01

과제 개요 및 목표

본 과제는 단순한 단발성 코드 구현이 아닌, 게임 시스템 전반의 플레이 루프와 오브젝트 상태 제어의 규칙성을 확립하는 것을 목표로 진행되었습니다.

기존의 절차지향적 조건문(if-else 중첩) 구조에서 발생하기 쉬운 스파게티 코드 및 상태 누락 문제를 해결하기 위해 인터페이스 기반의 유한 상태 머신(FSM) 아키텍처를 설계하여 적용했습니다.

🎯 상태 분리 및 캡슐화

각 상태(Patrol, Chase, Attack)를 독립된 클래스로 분리하여 상태 진입(Enter), 갱신(Update), 탈출(Exit) 라이프사이클을 보장했습니다.

⚡ 플레이어 감지 알고리즘

시야각(FOV) 및 거리 기반 레이캐스트를 조합하여 장애물 뒤에 숨은 플레이어를 비정상적으로 감지하지 않도록 처리했습니다.

📊 시각적 디버깅 지원

Unity Gizmos를 활용하여 에디터 씬 뷰에서 탐색 반경과 공격 유효 사거리를 실시간 와이어프레임으로 시각화했습니다.

SECTION 02

주요 설계 및 FSM 구조

적 오브젝트가 참조하는 IState 인터페이스와 상태 전이를 관리하는 EnemyStateMachine 핵심 구조입니다.

public interface IState { void Enter(); void Execute(); void Exit(); } public class EnemyStateMachine { public IState CurrentState { get; private set; } public void ChangeState(IState newState) { if (CurrentState == newState) return; CurrentState?.Exit(); CurrentState = newState; CurrentState.Enter(); } }

SECTION 04

트러블슈팅 및 배운 점

⚠️ 직면했던 문제

플레이어가 탐지 범위를 순간적으로 드나들 때 순찰과 추적 상태 간 전환이 매 프레임 반복(Chattering)되어 애니메이션과 이동이 튀는 현상 발생.

💡 해결 방법

진입 반경과 이탈 반경을 다르게 설정하는 히스테리시스(Hysteresis) 버퍼 및 상태 전이 최소 유지 시간(0.3초 쿨다운)을 적용하여 안정적인 자연스러운 전환 구현.
