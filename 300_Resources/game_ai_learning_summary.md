# 게임 개발과 AI 활용에 대한 자기 정리

## 내가 이미 알고 있던 것
- 나는 게임 콘텐츠를 만들거나, 기획서, 이력서, 발표 자료를 AI로 빠르게 정리해보는 작업에는 익숙해져 있었다.
- 최근에는 AI를 통해 서버 구조, DB 설계, 프로토콜, 무결성 검증 같은 백엔드적인 흐름까지 체험해보면서, 단순히 “코드 생성”이 아니라 실제 서비스 구조를 가볍게 실험해볼 수 있다는 걸 느꼈다.
- 게임에서 데이터가 클라이언트에서 변조되면 치팅이 가능해지고, 신뢰성이 떨어진다는 점은 이미 직감적으로 알고 있었다.
- 서버가 최종 상태를 계산하고 관리해야 한다는 생각은 이미 있었고, 그 과정에서 동시성, 상태 검증, 신뢰성 문제가 중요하다는 느낌을 갖고 있었다.
- 나는 백엔드 메이저가 되고 싶다는 생각보다는, 클라이언트 개발, 콘텐츠 제작, 기획, 시각적 구성, 3D, UI/UX까지 아우르는 게임 제작자로 성장하고 싶다는 방향이 더 맞다고 생각하고 있었다.

## 대화하면서 새롭게 발견한 것
- “AI를 잘 쓰는 것”은 정답을 빠르게 받는 것이 아니라, 실무자의 작업 흐름을 빠르게 흡수하고, 그 구조를 자기 방식으로 재현해보는 것이라는 점을 더 분명하게 느꼈다.
- 보안 문제는 단순히 비밀번호나 SSH 같은 접근 통제만이 아니라, “서버가 어떤 값을 신뢰할지”를 정하는 문제라는 걸 더 명확히 이해하게 되었다.
- 사용자 입력 검증은 단순히 이상한 값을 걸러내는 것뿐 아니라, 거래나 상태 변화가 실제로 가능한 상황인지 확인하는 데 더 큰 의미가 있다는 걸 알게 되었다.
- 서버는 최종 상태를 자기 기준으로 계산해야 하고, 여러 요청이 동시에 들어오는 상황에서도 동시성을 처리하는 로직이 있어야 한다는 점이 중요하다는 걸 이해했다.
- 내가 진짜 원하는 방향은 “게임 전체를 조율하고 구현하는 사람”이 되는 것이고, AI는 그 흐름을 실험하고 빠르게 학습하는 도구로 가치가 있다는 걸 발견했다.
- 내 관심사는 서버 자체보다, 훌륭한 기획을 바탕으로 콘텐츠를 만들고, 그 콘텐츠를 조작감 좋고 생산성 있게 구성하는 것에 더 강한 의미를 느끼고 있다는 것도 새로 드러났다.

## 더 알고 싶어진 것
- 내가 실제로 게임을 만들 때, 어떤 구조에서 클라이언트와 서버가 가장 잘 연결되는지 더 알고 싶다.
- 실무적인 게임 프로젝트에서는 “사용자 입력 검증”이 어떤 단계별로 이루어지는지, 특히 거래, 인벤토리, 상태 변경에서 어떤 검증이 필요한지 더 깊이 알고 싶다.
- 동시성 처리와 상태 검증이 실제로 어떻게 설계되는지, 클라이언트와 서버의 역할 분리가 어떤 식으로 이루어지는지 더 알고 싶다.
- AI를 활용해 기획 → 콘텐츠 생성 → 서버 연결까지 이어지는 전체 파이프라인을 어떻게 구성할 수 있는지 알고 싶다.
- 나는 게임 개발 전반을 연결하는 역할을 하고 싶다는 방향이 맞는지, 그리고 그 방향에서 어떤 기술을 먼저 익혀야 하는지 더 고민하고 싶다.
