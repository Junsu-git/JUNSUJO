2026 캡스톤 디자인 Unity 프로젝트

모듈형 FSM 아키텍처와 반응형 액션 시스템을 적용한 3D 전투 프로젝트

유한대학교 컴퓨터소프트웨어학과 게임콘텐츠전공 졸업 작품으로 진행되는 캡스톤 디자인 프로젝트입니다. 단순 프로토타입 수준을 넘어, 확장 가능한 C# 상태 머신(FSM) 아키텍처, 히트박스 판정 알고리즘, 그리고 기획자가 손쉽게 수치를 조정할 수 있는 ScriptableObject 기반 데이터 파이프라인을 구축하고 있습니다.

개발 기간 2026.09 — 2026.12 (진행 중)
수행 역할 메인 시스템 프로그래머 & 테크니컬 기획
사용 기술 Unity 2022.3 LTS · C# · FSM Pattern · Git-Flow
최종 목표 WebGL 데모 빌드 & 포트폴리오 메인 쇼케이스
SECTION 01

프로젝트 개요 및 기획 의도

본 캡스톤 프로젝트는 "명확한 피격 판정과 반응성 높은 전투 루프"를 목표로 기획되었습니다. 스파게티 코드가 되기 쉬운 적 AI와 플레이어 전투 로직을 인터페이스 기반으로 철저히 분리하여 유지보수성을 극대화했습니다.

⚔️ 반응형 액션 전투 루프

공격 선딜레이, 히트스탑(Hitstop), 넉백, 그리고 정확한 패링 타이밍 판정을 프레임 단위로 제어.

🧠 계층적 적 AI FSM

순찰(Patrol) → 의심(Suspicious) → 추적(Chase) → 스킬 콤보(Combo Attack) → 그로기(Groggy) 상태 전이 구조화.

📦 데이터 주도 설계 (Data-Driven)

모든 공격 판정 반경, 데미지 계수, 쿨다운 수치를 ScriptableObject 에셋으로 분리하여 기획적 밸런싱 편의 제공.

SECTION 02

프로젝트 비주얼 리뷰 & 시연 쇼케이스

인게임 3D 씬 와이어프레임 및 전투 프로토타입 시연 슬롯입니다.

3D ACTION SYSTEM · FSM AI 시야각 및 타격 판정 기즈모 뷰 UNITY SCENE VIEW & WEBGL PROTOTYPE
⚡
캡스톤 디자인 인게임 전투 및 AI 기즈모 시연 슬롯

3D 환경에서 적 AI가 플레이어를 감지하고 스킬 콤보를 전개하는 인게임 액션 녹화 GIF/스크린샷 및 WebGL 빌드 화면 배치 영역입니다.

🎯 시야각(FOV) 기즈모 시각화

에디터 상에서 적의 시야각 원뿔(Frustum)과 탐지 반경을 실시간으로 시각화하여 레벨 디자인 직관성 확보.

💥 타격 피드백 쉐이크 연출

Cinemachine 임펄스 소스를 활용해 공격 적중 시 묵직한 카메라 쉐이크 및 파티클 이펙트 동기화.

SECTION 03

확장 가능한 FSM 상태 전이 아키텍처

모든 몬스터와 보스 객체가 공유하는 IState 인터페이스 및 상태 전이 제어기 코드입니다.

// 공통 유한 상태 머신 인터페이스 public interface IState { void OnEnter(); void OnUpdate(); void OnExit(); } // 보스 및 정예 몬스터 상태 머신 컨트롤러 public class BossStateMachine : MonoBehaviour { public IState CurrentState { get; private set; } private float stateTimer; public void TransitionTo(IState nextState) { if (CurrentState == nextState) return; CurrentState?.OnExit(); CurrentState = nextState; stateTimer = 0f; CurrentState.OnEnter(); } }
SECTION 04

개발 마일스톤 및 추진 계획

1단계: 플레이 루프 및 기본 FSM 완성 (9월 완료)

플레이어 이동, 기본 3타 공격 콤보, 적 AI 순찰/추적 상태 머신 베이스라인 구축 완료.

2단계: 패링 및 히트 판정 시스템 고도화 (10월 중순)

정밀 충돌 감지 콜라이더, 저스트 패링 시 슬로우 모션(Bullet Time) 효과 및 특수 반격기 연동.

3단계: 보스전 페이즈 및 기믹 구현 (11월 초)

체력 구간별 2페이즈 변신 연출, 광역 바닥 장판 공격 패턴 및 그로기 딜타임 메커니즘 개발.

4단계: 사운드 연출, WebGL 최적화 및 최종 배포 (11월 말 ~ 12월)

UI 폴리싱, 웹 브라우저 플레이 최적화 및 졸업작품 최종 심사 패키지 완성.
