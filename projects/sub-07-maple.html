PROJECT / WORK RECORD

메이플 키우기 데이터 분석

14일간 4개 계층의 지표를 기록하고 표시 전투력과 실제 데미지의 차이를 비교한 QA·밸런스 분석입니다.

SUB-07팀장 · 로깅 모델·분석3학년 1학기 (2026.03 ~ 2026.06)

관찰과 검증

표시 전투력의 상승이 실제 데미지 상승과 같은 비율로 이어지는지 확인했습니다. 관측 결과와 내부 공식에 대한 가설을 구분하고, 재현 가능한 테스트 케이스로 정리했습니다.

분석 개요

3인 팀 토끼와거북이의 SWTestQA 과제입니다. 신규·5n·6n·7n 계층의 계정을 대상으로 14일간 플레이 지표를 기록했습니다. 저는 팀장으로서 로깅 항목과 비교 기준을 설계하고 분석 및 발표 자료 제작을 담당했습니다.

데이터와 비교 기준

아래는 최종 발표자료에 정리된 값입니다. 라이브 서비스 전체 이용자의 통계가 아닌 수업의 블랙박스 테스트 결과입니다.

7n 계정 1일차 14일차
레벨 73 81
표시 전투력 1,292,880,000 6,177,450,000
데미지 104,585,202 302,512,687

전투력 대비 데미지 비율의 변화는 (말기 데미지 / 말기 전투력) / (초기 데미지 / 초기 전투력) - 1로 비교했습니다. 발표자료는 약 39.5% 감소로 정리합니다. 이를 게임 내부 공식의 오류나 유저 이탈의 인과 증명으로 확대하지 않습니다.

담당 역할

  • 레벨 구간별 로깅 모델과 수집 항목 정의
  • 전투력·데미지·성장 던전·장착 무기 비교
  • 챕터 이동과 다중 기기 접속에 대한 QA 테스트 케이스 제안
  • 분석 스토리보드와 발표 자료 작성

수집 과정

실시간 버프로 수치가 달라지는 문제를 발견해 2일차부터 기본 능력치 상세 값을 기록하도록 기준을 통일했습니다. 게임 화면에서 확인한 값을 수동으로 기록했으며, 내부 서버 로그를 직접 수집한 분석은 아닙니다.

개선 제안

무기 획득에 집중된 성장 체감을 누적형 강화 요소로 분산하고, 공격 기여도와 생존 기여도를 구분한 지표를 제안했습니다. QA에서는 챕터 반복 이동 후 몬스터 수·시간당 보상 비교, 두 번째 기기 로그인 시 기존 세션 만료 여부 등을 테스트 항목으로 정리했습니다. 운영사의 실제 수정 완료를 검증한 결과로 표현하지 않습니다.

분석의 한계

표시 전투력만으로 실전 성능을 설명하기 어렵다는 점과 수집 조건을 고정하는 중요성을 배웠습니다. 표본과 측정 기간이 제한적이며 버프·장비·길드 등 조건을 완전히 분리하지 못했습니다. 로깅 시트의 반올림된 평균 값과 발표자료의 정리 값은 구분해서 읽어야 합니다.
